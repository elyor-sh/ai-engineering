## Эксперимент 1. Один текст — разные исходы (15 минут)

```bash
uv run python $P/01_streaming.py
```

Во всех четырёх сценариях видимая фраза — «Привет, Алекс!». Но решение клиента различается:

| Сценарий | Принять текстовую пару? | Что с ценой? |
|---|---|---|
| `stop`, нормальный конец, поздний usage | Да | Есть оценка условного тарифа |
| `stop`, нормальный конец, usage отсутствует | Да | Неизвестна |
| Итератор закончился без finish reason | Нет | Итог не подтверждён |
| `length`, нормальный конец, usage есть | Нет | Оценка расхода возможна |

«Итератор закончился нормально» здесь значит только, что обход SDK не выбросил исключение. Это **не** автоматическое подтверждение завершения самой модели.

Числа `100` входных и `20` выходных токенов **заданы в фикстуре**. Они не получены подсчётом этой приветственной фразы или количества chunks.

### Задание 1.2. Не выходи слишком рано

Если прекратить цикл сразу при `finish_reason=stop`, что случится с последним отчётом в исходном сценарии? Нужна ли передача новых символов, чтобы событие было важным?

### Задание 1.3. Сохрани пробел

Как отдельно хранить показанный черновик для диагностики, не выдавая его за принятую реплику? Какие правила приватности понадобятся таким журналам?

## Эксперимент 3. Стоимость без двойного счёта (10 минут)

В локальной демонстрации используется **выдуманный двухставочный тариф**:

```text
$1 за 1М prompt-токенов
$5 за 1М completion-токенов
100 входных и 20 выходных → $0.0002
```

Это не прайс Gemini или OpenRouter. Все input здесь имеют одну ставку, все output — другую; нет отдельной скидки, налога или счёта инструментов.

### Задание 3.1. Вложенные категории

В тесте с детализацией:

- `prompt_tokens=100`, внутри `cached_tokens=60`;
- `completion_tokens=20`, внутри `reasoning_tokens=10`.

Почему нельзя считать `160` входных и `30` выходных? Какая документация потребовалась бы для другого тарифа или другого смысла полей?

### Задание 3.2. Снимки — не приращения

В одном тесте сначала приходит снимок `100/5`, затем итоговый `100/20`.

Сложение дало бы `200/25`. Почему это повторный учёт, а не новая порция расхода? Где в коде сохраняется именно последний доступный снимок?

### Задание 3.3. Ноль и неизвестность

Найди `test_reported_zero_and_unknown_are_distinct`. Почему отчёт с нулевыми счётчиками в рамках нашего контракта — другой случай, чем отсутствие usage или ставок?

Почему даже правильный расчёт через Decimal не является окончательной квитанцией настоящего провайдера?

## Живой режим — необязательный

За один запуск выполняется **один запрос**, не цикл чата. Для первого знакомства достаточно локальных сценариев и тестов.

### Gemini

Используются твои `GEMINI_API_KEY` и `MODEL_GEMINI` из окружения или корневого `.env`. Можно передать реальную модель явно через `--model`. Устаревший ID автоматически не подставляется.

```bash
uv run python $P/01_streaming.py --live --provider gemini
```

Текст начнёт появляться по мере поступления дельт. Не отправляй персональные сведения или внутренние документы.

**Usage по умолчанию специально не запрашивается отдельной опцией**, чтобы не выдавать её поддержку за универсальную. Если документация твоего endpoint подтверждает `stream_options.include_usage`, можно явно добавить:

```bash
uv run python $P/01_streaming.py --live --provider gemini --include-usage
```

Не нужно выполнять оба запроса ради галочки: сначала проверь поддержку. Каждый новый запуск — отдельная попытка. При ошибке неподдерживаемой опции программа не повторяет запрос автоматически без неё.

### Ollama

Запусти приложение и проверь установленную **действительно локальную** модель:

```bash
open -a Ollama
ollama list
```

Если в списке есть знакомая `qwen3.5:4b`, пример запуска:

```bash
uv run python $P/01_streaming.py --live --provider local --model qwen3.5:4b
```

Можно использовать `MODEL_LOCAL` вместо аргумента. Endpoint фиксирован как localhost; однако локальный адрес сам по себе не доказывает локальность выбранной модели. Не выбирай облачный тег или перенаправляющий алиас, если нужен полностью локальный опыт.

### Ставки в живом режиме

Без явно заданных ставок денежная оценка не выполняется. Наличие usage само по себе не сообщает актуальный прайс.

Параметры принимают десятичные значения USD за миллион токенов:

```text
--input-rate ЦЕНА_ВХОДА_ЗА_1М --output-rate ЦЕНА_ВЫХОДА_ЗА_1М
```

Не копируй учебные `1` и `5` как настоящий тариф сервиса. Для скидок на кэш, других категорий и сборов простой калькулятор может не подходить. Проверяй документацию и источник цены.

### Отмена и ограничение длины

- **Ctrl+C** во время чтения помечает попытку как отменённую и закрывает клиентский поток.
- `--max-tokens` ограничивает генерацию, но не гарантирует размер видимого текста.
- Тайм-аут ожидания клиента — 30 секунд, автоматические повторы SDK отключены.
- Неудачная попытка в живом режиме завершает программу с ненулевым кодом; локальные демонстрации намеренно показывают разные исходы и завершаются нормально.

Часть текста могла уже появиться до отмены. Это черновик, а не обещание успеха. Расход удалённой стороны при обрыве нельзя объявлять нулевым без подтверждения.

## Автоматические проверки

```bash
uv run python -m unittest discover -s "$P" -v
```

Ожидается **21 тест, OK**. Проверяются:

- точная склейка текста без потери пробелов;
- роль, поздний usage и события без choices;
- EOF без завершения, length, отмена и разрыв;
- отдельные исходы инструментов и refusal в узком текстовом контракте;
- запрет текста после объявленного finish;
- последний usage вместо суммы снимков;
- вложенные cached/reasoning без двойного учёта;
- неизвестная цена против нулевого отчёта;
- добавление в историю только принятого результата;
- закрытие потока, опциональный запрос usage и безопасный режим по умолчанию.

В тестах live-ветка использует **подменённую сетевую границу**. Настоящие ключи и квоты не расходуются, доступность Gemini/Ollama не проверяется. Реальные генеративные запросы при подготовке урока не запускались.

## Границы реализации

Это синхронный потребитель одного текстового варианта совместимого Chat Completions. Он не является универсальным адаптером Responses API, родных событий Gemini/Anthropic, мультимодальности или инструментов.

Usage рассматривается как снимок агрегата попытки; для другого контракта нужен другой разбор. Цена — условная оценка по двум ставкам и подтверждённым по правилам лаборатории данным, не реальный биллинг.

Нет сохранения на диск, автоматических повторов, возобновления оборванного потока, общего месячного счёта и production-мониторинга. Ошибки программирования не прячутся общим `except Exception`: обрабатываются ожидаемые ошибки API, транспорта, протокола и отдельная отмена.
