## Эксперимент 2. Живой чат — по желанию (15–20 минут)

Если пока хочешь изучать только структуру, пропусти этот раздел: автоматические проверки работают без сети.

### Gemini

Для живого режима нужны переменные окружения или строки в `.env`:

- `GEMINI_API_KEY` — твой существующий ключ Gemini API;
- `MODEL_GEMINI` — точный ID доступной модели, например той, которая отвечала в твоём предыдущем упражнении.

В коде **нет автоматического имени модели Gemini**: не будем повторять проблему устаревшей или недоступной версии. Если значения нет, программа попросит указать его.

```bash
uv run python $P/01_chat_api.py --live --provider gemini
```

Можно передать модель явно аргументом `--model`, заменив учебный пример ниже своим действительным ID:

```text
uv run python $P/01_chat_api.py --live --provider gemini --model ID_ТВОЕЙ_МОДЕЛИ
```

Не передавай ключ аргументом командной строки и не отправляй его в чат.

`.env` загружается из корня проекта только в живом режиме. Уже установленные переменные процесса не переопределяются: если настройки расходятся, проверь, не задано ли другое значение в окружении терминала.

### Ollama на localhost

```bash
open -a Ollama
ollama list
```

Выбери **действительно локальную** генеративную модель. Например, если в твоём списке есть установленная `qwen3.5:4b`:

```bash
uv run python $P/01_chat_api.py --live --provider local --model qwen3.5:4b
```

Или задай `MODEL_LOCAL` в своём окружении и опусти `--model`.

В этой лаборатории endpoint локальной ветки фиксирован: `http://localhost:11434/v1`. Скрипт не использует `OLLAMA_BASE_URL` и не переключается на внешний сервер при ошибке.

**Важно:** localhost — адрес API, не доказательство локальности всех вычислений. Не выбирай облачный вариант или алиас, который маршрутизирует модель наружу, если тебе нужен локальный опыт. Как и в уроке 2.1, маршрут и модель проверяют отдельно. Этот учебный клиент не является сетевым firewall.

### Диалог для опыта

Введи по очереди:

```text
Меня зовут Алекс. Отвечай коротко.
Как меня зовут?
/reset
Как меня зовут?
/exit
```

Используй вымышленное имя; рабочие документы и личные сведения не нужны.

Что проверить:

- после принятой реплики растёт число завершённых пар;
- второй запрос получает историю с именем;
- `/reset` очищает историю процесса;
- следующий запрос не содержит прежней пары;
- `/exit` завершает цикл.

Текст настоящей модели может отличаться от ожидаемой формулировки. Не оценивай correctness клиента только по тому, насколько приятно она ответила: проверь состав запроса и фактическое состояние.

### Задание 2.1. Почему память стоит токенов

Сравни входной usage первого и второго успешного хода. Почему он обычно растёт? Совпадёт ли цена у всех моделей при одинаковом тексте?

Если usage отсутствует, программа честно пишет, что отчёт не получен, а не подставляет нулевой расход.

### Задание 2.2. Сброс — локальная операция

Что именно очищает `/reset`? Удаляет ли эта команда журналы провайдера или меняет веса модели? Почему ответ о сохранении данных должен опираться на контракт сервиса, а не на слова ассистента?

### Задание 2.3. Маленький лимит

По желанию запусти отдельную короткую сессию:

```bash
uv run python $P/01_chat_api.py --live --provider gemini --max-tokens 8
```

Если сервер сообщает `length`, клиент не добавит обрезанный текст как завершённую пару. Но точный исход зависит от модели: она может закончить раньше или потратить бюджет на промежуточную работу. Этот опыт не обязан давать одну и ту же форму ответа в любом API.

Если лимит или само имя параметра не поддерживаются, это тоже нужно обработать как несовместимость, а не бесконечно повторять запрос. Для текущего учебного Chat Completions используем `max_tokens`; другие API могут требовать другой контракт.

## Автоматические проверки

```bash
uv run python -m unittest discover -s "$P" -v
```

Ожидается **18 тестов, OK**. Вместо сети используются заранее заданные структуры ответа SDK. Проверяются:

- роли, порядок и неизменность исходной истории;
- отсутствие повышения роли по тексту пользователя;
- новая завершённая пара только после подходящего результата;
- ошибки, обрезка, отсутствие текста, refusal и tool calls;
- явные модель и маршрут без скрытого fallback;
- отсутствие чтения `.env`, клиента и интерактивного ввода в preview;
- тайм-аут, отключённые автоматические повторы и отсутствие вывода ключа;
- очистка истории перед следующим запросом после `/reset`.

Тест с названием live проверяет ветку программы **с подменённой сетью**, а не вызывает настоящий Gemini. Тесты подтверждают контракт клиента, не доступность сервиса и не качество модели. Реальная генерация в этой сессии подготовки урока не запускалась.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Нет `MODEL_GEMINI` или `MODEL_LOCAL` | Укажи действительный ID в окружении или через `--model`; автоматического подбора нет |
| Нет `GEMINI_API_KEY` | Для облачной ветки нужен ключ API, не только подписка на чат; в код его не вставляем |
| HTTP 401/403 | Ключ, разрешения и проект |
| HTTP 404 | Адрес интерфейса и модель на этом сервере; у Ollama — наличие в `ollama list` |
| HTTP 429 | Квоты и частота; не пытайся лечить это немедленным циклом повторов |
| HTTP 5xx / тайм-аут | Доступность сервиса или модели; проверка ключа не гарантирует генерацию |
| `length` / пустой ответ | Лимит и особенности модели, включая рассуждения; не считай частичный результат полным |
| Программа показывает только JSON | Это безопасный preview. Настоящий чат включается `--live` |

Пока нет сохранения на диск, автоматического сжатия истории, стриминга, инструментов, точного бюджета контекста и полной политики повторов. Длинный диалог может выйти за лимиты API. Это заготовка «Знайки», а не production-сервис.
