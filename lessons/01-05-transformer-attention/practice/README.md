## Эксперимент 1. Смотрим на одну голову (15–20 минут)

```bash
uv run python $P/01_attention_weights.py
open $P/out/01_attention_weights.png
```

Программа показывает:

1. Матрицу `X`: по одному вектору на условную позицию.
2. Три преобразования `X @ Wq`, `X @ Wk`, `X @ Wv`.
3. Веса внимания: по строкам получатели, по столбцам источники.
4. Результат смешивания `weights @ V`.

### Задание 1.1. Прочитай карту правильно

Возьми строку «она» и перечисли веса трёх источников. Их сумма должна быть примерно один. Это распределение вклада **позиций**, а не вероятности следующих слов.

Здесь наибольший вес может оказаться у самой позиции «она». Не нужно подгонять числа, чтобы программа будто бы «нашла кошку»: наши векторы и матрицы никто не обучал разрешать местоимения.

### Задание 1.2. Смешай значения вручную

Найди в выводе три вектора `V`. Умножь каждый на его вес в выбранной строке и сложи. Сравни с соответствующей строкой `output`.

Для независимой проверки числового примера из теории:

```text
Веса: 0.7, 0.2, 0.1
V: [10, 0], [0, 10], [5, 5]
Результат: [7.5, 2.5]
```

Почему получился новый вектор, а не один случайно выбранный исходный?

### Задание 1.3. Что меняет веса, а что — содержимое

В `01_attention_weights.py` меняй по одной вещи и каждый раз запускай скрипт:

- Измени `wv`, оставив `wq` и `wk` прежними. Изменилась ли карта внимания? А результат `output`?
- Затем верни `wv` и измени `wk`. Что произошло с картой?

Это показывает разницу между **сопоставлением Q и K** и **передачей V**. Не меняй всё одновременно: тогда потеряется причина результата.

### Задание 1.4. Найди операции в ядре

Открой `attention_core.py` и найди:

- скалярные произведения через матричное умножение;
- деление на квадратный корень из размерности;
- softmax по источникам;
- взвешенную сумму значений.

Есть ли здесь деление Q и K на их длины, как при вычислении косинуса в уроке 1.4?

## Эксперимент 2. Закрываем будущее (15–20 минут)

```bash
uv run python $P/02_causal_mask.py
open $P/out/02_causal_mask.png
```

В этом опыте `Q = K = V = X`. Это соответствует единичным проекциям для учебного случая. Никакого обучения или настоящего позиционного кодирования здесь нет.

### Что должно быть видно

- Без маски ранняя позиция может получать информацию от поздней.
- С маской все веса правее диагонали равны нулю.
- Первая позиция с маской имеет один доступный источник — себя; её первый вес равен единице.
- У последней позиции маска ничего не запрещает, поэтому её строка совпадает с вариантом без маски.

### Задание 2.1. Не только картинка

Скрипт заменяет последний входной вектор. В выводе должны быть две строки:

```text
Ранние результаты без маски сохранились: False
Ранние результаты с маской сохранились: True
```

Объясни, почему такая проверка полезнее одной картинки треугольной матрицы. Включает ли проверка последний выход? Должен ли он обязательно сохраняться?

### Задание 2.2. Почему обычного нуля недостаточно

Найди в `attention_core.py`:

```python
scores = np.where(future, -np.inf, scores)
```

Мысленно или в отдельной копии замени `-np.inf` на `0.0`. Что softmax сделает с запрещённой клеткой? Вернётся ли ненулевой вес?

Если меняешь исходник, запусти тесты: проверка нулевых будущих весов и независимости от будущего должна обнаружить проблему. Затем верни правильную маску.

### Задание 2.3. Перестановки — два разных утверждения

В конце скрипта отдельно проверяется **полное внимание без маски и позиционных сигналов**:

```text
Выходы переставились так же: True
Выходная последовательность осталась буквально прежней: False
```

Почему эти результаты не противоречат друг другу? Какую информацию нужно добавить, чтобы модель учитывала позицию, а не только содержимое и отношения между векторами?

Не делай из этого опыта вывод, что causal attention с маской тоже допускает любую перестановку: маска сама зависит от порядка.

### Мои наблюдения

```text
2.1 Проверка будущего означает …; последний выход …
2.2 После замены -inf на 0 …
2.3 Перестановка выхода и неизменность выхода отличаются тем, что …
```

## Автоматические проверки

```bash
uv run python -m unittest discover -s "$P" -v
```

На исходном коде ожидается **14 тестов, OK**. Они проверяют:

- суммы строк и устойчивость softmax на больших баллах;
- нулевые веса запрещённых источников;
- отказ от полностью замаскированной строки и некорректных чисел;
- масштабирование через корень из размерности;
- взвешенное среднее вместо случайного выбора V;
- отсутствие влияния будущего в причинном режиме;
- свойство перестановки в полном attention без позиций;
- согласованность размеров Q, K и V.

Тесты подтверждают математику учебного блока, а не понимание языка или качество готового ассистента.

## Границы реализации

Здесь одна голова без dropout, multi-head объединения, KV-cache, MLP, остаточных связей, нормализаций и RoPE. Причинная маска рассчитана на одинаковую длину Q и K в полном self-attention; это не универсальная маска для пошагового декодирования с кэшем.

Две картинки — иллюстрация вычислений. Они не объясняют автоматически решения настоящего ChatGPT или Gemini.
