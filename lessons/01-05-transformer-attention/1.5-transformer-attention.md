В трансформере тоже нет маленьких людей внутри: работают вычислительные блоки и обученные числа.

**Урок 1.3 «Токены и токенизация».** Текст превращается в последовательность токенов и их ID. Токен не равен слову, а размер запроса измеряется не количеством видимых букв. Важно оставить место для ответа и учитывать собственный токенизатор выбранной модели.

**Урок 1.4 «Эмбеддинги».** ID выбирает начальный вектор из таблицы. Затем слои модели могут превратить его в контекстное представление, а отдельная модель эмбеддингов — собрать вектор целого текста для поиска. Косинусное сходство не является вероятностью истины: похожие по теме инструкции могут противоречить друг другу. Сравнивать векторы нужно в согласованном пространстве.

### Как с этим связан этот урок

В прошлом уроке остался вопрос: **как вектор токена узнаёт, что находится вокруг?** Почему слово в предложении о еде может получить другое представление, чем тот же фрагмент в предложении об оружии?

Сегодня разберём один из главных механизмов обмена информацией между позициями — attention. Затем увидим, как он соединяется с остальными блоками трансформера и как из этого получается предсказание следующего токена.

## 🎯 Зачем этот урок

Когда ассистент отвечает по длинной переписке, ему нужно использовать связи между удалёнными частями текста. Определение термина может быть в начале, вопрос — в конце, а важное исключение — посередине.

Понимание трансформера помогает объяснить:

- почему модель учитывает контекст, но всё равно может ошибаться;
- зачем нужны Query, Key и Value;
- почему при обучении нельзя разрешать подсматривание в продолжение;
- чем внимание внутри модели отличается от поиска по документам;
- почему длинный контекст требует ресурсов;
- почему вход можно обрабатывать параллельно, а ответ обычно генерируется последовательно.

Нам не нужно запоминать всю архитектуру наизусть. Цель — собрать знакомые операции в понятную схему и не перепутать её с человеческим сознанием.

---

## 🗣 Почему одного словаря недостаточно

Возьмём фразу: «Кошка устала и легла на коврик. Она сразу уснула».

Чтобы использовать «она», полезно связать эту позицию с предыдущим упоминанием кошки. Чтобы понять действие, важны «уснула», «устала» и другие части контекста. Если обрабатывать каждый токен независимо, эти связи не появятся.

В реальном тексте слова могут разбиваться на несколько токенов. Для удобства объяснения будем говорить о словах, но вычисления происходят над позициями токенов.

Представь редакцию, где у каждого фрагмента текста есть маленькая рабочая карточка — его текущий вектор. Нужен способ запросить информацию у других карточек и обновить свою. **Attention — механизм такого взвешенного обмена**.

Он не обязательно выбирает одного соседа и не обязан совпадать с тем, на что посмотрел бы человек. Обычно информация приходит сразу от нескольких разрешённых позиций с разными весами.

## 🪪 Query, Key и Value: три роли одного представления

Для внимания из текущих векторов получают три набора: **Query, Key, Value**, сокращённо Q, K и V.

Их удобно понимать как три карточки одной позиции.

**Query — запрос: «какая информация мне сейчас нужна?»**

**Key — признак для сопоставления: «по чему другие могут понять, что я им подхожу?»**

**Value — содержимое для передачи: «какую информацию я передам, если ко мне обратятся?»**

В редакционной аналогии сотрудник формулирует свой вопрос, смотрит на описания коллег и собирает их сообщения. Но в модели нет буквальных вопросов на русском: все три карточки — векторы чисел.

Важно не перепутать названия. Key здесь не секретный API-ключ, а Query не обязательно пользовательский вопрос из интерфейса. Такие векторы создаются для позиций внутри сети.

### Откуда берутся три карточки

Текущее представление умножают на три обучаемые матрицы: одну для Q, другую для K, третью для V. В некоторых реализациях есть и дополнительные детали, например смещения.

Это знакомое преобразование из урока 1.1. При обучении веса матриц настраиваются вместе с остальной моделью. При обычном инференсе они не переучиваются на каждом запросе.

Почему не использовать один и тот же вектор для всего? Разные преобразования позволяют разделить задачу сопоставления и содержимое передачи. «По каким признакам меня искать» не обязано совпадать с «что именно я сообщаю».

## ⚖️ Как получаются веса внимания

Теперь выберем одну позицию-получателя и пройдём четыре шага.

### Шаг первый: сравнить запрос с ключами

Берём Query выбранной позиции и считаем скалярное произведение с Key каждой доступной позиции. Получаем список сырых баллов соответствия.

Здесь есть важное отличие от прошлого урока. Стандартный **scaled dot-product attention** не обязан считать косинусное сходство. Векторы Q и K обычно не приводятся к единичной длине ради этого вычисления. Их преобразования обучены для своей задачи.

Поэтому полезно помнить операцию, а не переносить вслепую все правила поиска по эмбеддингам.

### Шаг второй: отмасштабировать баллы

Баллы делят на квадратный корень из размерности ключей. Это помогает контролировать их масштаб: при больших размерностях сырые произведения могут становиться слишком большими, а softmax — чрезмерно резким.

Не нужно сейчас выводить эту поправку. Главное: это техническое масштабирование внутри attention, а не пользовательская температура генерации из API.

### Шаг третий: учесть запреты и применить softmax

Если некоторым позициям смотреть друг на друга нельзя, их исключают с помощью маски. Затем softmax превращает разрешённые баллы в неотрицательные веса, которые в сумме дают один для каждой позиции-получателя.

Обрати внимание, **по чему распределяются веса**: по позициям-источникам в текущем контексте, а не по всем возможным следующим токенам словаря.

### Шаг четвёртый: смешать Value

Каждый Value умножается на соответствующий вес, результаты складываются. Получается новый вектор информации для выбранной позиции.

Например, веса равны семи десятым, двум десятым и одной десятой. Пусть передаваемые векторы — «десять, ноль», «ноль, десять» и «пять, пять». Результат смешивания — «семь с половиной, два с половиной».

Это не выбор одного сообщения по лотерее. При обычном вычислении attention мы **суммируем взвешенные векторы**, а не случайно выбираем одного соседа. Сэмплирование следующего токена — другой этап.

## 🧮 Один запрос или целая матрица

Те же действия можно выполнить сразу для всех позиций. Матрица Q сравнивается с матрицей K, получаются баллы «каждый получатель — каждый источник». Затем применяются маска, softmax и умножение на V.

При обычном self-attention для последовательности из ста токенов матрица весов имеет сто строк и сто столбцов. Строка отвечает на вопрос: **откуда эта позиция получает информацию?**

Если нарисовать такую таблицу цветами, получится тепловая карта внимания. Яркая клетка означает большой вес конкретной связи в конкретной голове и слое.

В практике мы построим маленькую карту и проверим, что разрешённые веса каждой строки суммируются в единицу. Сама карта — не ответ модели и не доказательство понимания языка.

## 👥 Self-attention и несколько голов

**Self-attention** означает, что Q, K и V получаются из одной обрабатываемой последовательности представлений. Позиции обмениваются информацией внутри неё.

Это не значит, что токен может смотреть только на себя. Наоборот: именно здесь он может получать сведения от других разрешённых позиций.

Существует и **cross-attention**: запросы могут приходить из одной последовательности, а ключи и значения — из другой. Такой механизм, например, используется в классических encoder-decoder архитектурах. Но он не обязателен в каждой современной чат-модели.

### Зачем несколько голов

Одного способа сопоставления может быть мало. Поэтому делают несколько **голов внимания**. Каждая использует свои преобразования и получает собственную карту весов. Их результаты объединяют и снова преобразуют в представление нужного размера.

Аналогия: один редактор смотрит на грамматические связи, другой — на тему, третий — на дальние зависимости. Это только образ. Нельзя заранее гарантировать, что каждая реальная голова получит одну понятную человеку специальность.

Больше голов само по себе не означает лучший интеллект. Важны архитектура, обучение и распределение ресурсов. Наш учебный код реализует одну голову, чтобы механизм был виден без лишних деталей.

---

## 🚧 Причинная маска: не подсматривать в продолжение

Вернёмся к задаче предсказания следующего токена. Если модель в процессе обучения увидит тот токен, который должна угадать, получится экзамен с ответом прямо перед глазами.

Для авторегрессионной генерации используют **causal mask**, причинную маску. Позиции разрешено учитывать себя и предыдущие позиции, но не более поздние.

Если токены идут слева направо, в матрице внимания запрещены клетки правее диагонали. После softmax их вес равен нулю.

В вычислении удобно до softmax заменять запрещённые баллы на минус бесконечность: экспонента от такого значения даёт ноль. Одной замены балла на обычный ноль недостаточно — softmax всё ещё мог бы выделить ему ненулевой вес.

### Что именно модель предсказывает

Пусть на входе «Я вижу дом». Представление на позиции «вижу» при обучении может учитывать «Я» и «вижу», но не «дом». По этому представлению модель должна предсказывать следующий токен, который в учебном тексте соответствует продолжению.

Целевые ответы сдвинуты относительно входных позиций. Это позволяет обучать много предсказаний за один проход по последовательности, не подглядывая в будущее.

### Наглядная проверка

Если заменить последний входной вектор, результаты на более ранних позициях в корректном causal self-attention не должны измениться. У этих позиций нет пути к изменённому будущему в пределах такого вычисления.

Без маски ранние позиции могут измениться. Именно эту разницу проверим в практике — это сильнее, чем просто нарисовать красивый треугольник.

## 📍 Как модель узнаёт порядок

Слова «кот догнал пса» и «пёс догнал кота» состоят из похожего набора деталей, но означают разные события. Значит, модели нужна информация не только о содержимом, но и о позициях.

У полного self-attention без маски и позиционных сигналов есть особое свойство: если согласованно переставить входные строки, выходные строки переставятся соответствующим образом. Сам механизм не привязывает содержимое к конкретному абсолютному номеру места.

Это не означает, что выходные последовательности буквально одинаковы: они тоже переставляются. Важно не перепутать «одинаковый результат» и «та же перестановка результата».

Для представления порядка используют **позиционную информацию**. В одних архитектурах позиционные векторы добавляют к входам. В других, например при RoPE, позиция влияет на преобразование Query и Key через вращения, позволяющие учитывать относительное положение.

Причинная маска тоже задаёт ограничение порядка — кто находится в прошлом. Но маска и позиционный механизм выполняют разные задачи и не являются взаимозаменяемыми деталями.

Мы не будем реализовывать RoPE в этом вводном уроке. Важнее понимать: «начальные векторы токенов» — ещё не вся информация, с которой работает настоящий трансформер.

## 🧱 Трансформер — это не один attention

Мы разобрали важный механизм, но модель состоит не только из него. Типичный блок современного языкового трансформера включает несколько частей.

**Attention переносит и смешивает информацию между позициями.**

**Feed-forward блок**, или MLP, преобразует представление каждой позиции с помощью обученных матриц и нелинейностей. В обычном таком блоке сами позиции обрабатываются независимо друг от друга, хотя до него их векторы уже могли получить контекст через attention.

**Остаточные связи**, residual connections, добавляют обновление к предыдущему представлению вместо полной замены. Это помогает сохранять информацию и обучать глубокие сети. Размеры перед сложением должны быть согласованы, поэтому выходы нужным образом проецируют.

**Нормализации**, например LayerNorm или RMSNorm, контролируют масштаб представлений. Не путай их автоматически с приведением поискового эмбеддинга к единичной длине из урока 1.4: это другие операции с другими целями.

Порядок операций и конкретные детали различаются между архитектурами. Несколько блоков идут друг за другом, и контекстные представления постепенно преобразуются.

Полезный образ: attention собирает сведения от коллег, MLP перерабатывает их на рабочем месте, остаточная связь сохраняет прежние заметки вместе с обновлением, а нормализация удерживает рабочий масштаб чисел.

## 🏛 Три семейства архитектур

Трансформер был представлен в статье «Attention Is All You Need» в 2017 году. Исходная архитектура предназначалась для задач вроде перевода и содержала encoder и decoder. Сегодня важны несколько семейств.

**Encoder-only.** Обрабатывает вход, обычно позволяя позициям учитывать контекст с обеих сторон. Известный пример семейства — BERT. Такие архитектуры часто используют для представлений и понимания текста.

**Decoder-only.** Обычно использует причинное self-attention и предсказывает продолжение. Это основа многих современных генеративных языковых моделей.

**Encoder-decoder.** Encoder обрабатывает исходную последовательность, а decoder генерирует другую, обращаясь к представлению входа через cross-attention. Такой вариант удобен для преобразования одной последовательности в другую.

Не превращай это в жёсткое правило «эмбеддинги бывают только у encoder». Модели текстовых эмбеддингов могут строиться и на других основах. А не вся существующая языковая модель обязана быть стандартным трансформером: есть альтернативные и гибридные архитектуры.

Для нашего пути к чат-приложениям сейчас важнее всего уверенно понимать причинный decoder-only вариант.

## 🔤 От представления — к следующему токену

Теперь соединим цепочку целиком.

Текст токенизируется. По ID выбираются начальные векторы. Модель учитывает позиционную информацию и прогоняет представления через блоки. На выходе нужной позиции получается вектор, из которого отдельное преобразование вычисляет **логиты по словарю**.

Дальше softmax и стратегия выбора определяют следующий токен. Он добавляется к последовательности, после чего можно предсказывать следующий.

Здесь встречаются **два разных применения softmax**:

- внутри attention он распределяет веса между позициями-источниками;
- на выходе генератора он превращает логиты словаря в распределение следующего токена.

Это разные оси и разные задачи. Большое внимание к фрагменту «возврат» само по себе не означает, что следующим токеном обязательно будет «возврат».

### Параллельный вход, последовательный выход

При обучении и обработке готового входа многие позиции можно вычислять параллельно: матрицы содержат сразу всю известную последовательность, а причинная маска ограничивает доступ.

При обычной авторегрессионной генерации будущие выходные токены ещё неизвестны. Чтобы получить следующий шаг, нужно сначала выбрать предыдущее продолжение. Поэтому остаётся последовательная зависимость.

На практике есть кэширование и разные ускорения. В частности, KV-cache позволяет переиспользовать часть уже вычисленных ключей и значений. Подробно поговорим об этом в уроке 1.7. Кэш вычислений не равен постоянной памяти пользователя и не отменяет управление историей в приложении.

---

## 📦 Почему длинный контекст требует ресурсов

В простом полном self-attention каждый токен сопоставляется с каждым. Для тысячи токенов это миллион пар в одной карте; для двух тысяч — четыре миллиона. При удвоении длины число таких пар увеличивается в четыре раза.

Это объясняет часть стоимости длинного контекста. Но не нужно делать вывод, что время любого реального запроса строго растёт в четыре раза: есть другие блоки, разные режимы вычислений, кэш и оптимизации.

Оптимизированные реализации, например FlashAttention, могут не хранить всю большую матрицу весов одновременно и существенно улучшать использование памяти. Некоторые архитектуры ограничивают связи иначе. Наша маленькая NumPy-реализация намеренно материализует матрицу — так проще увидеть механизм.

Вспомни урок 1.3: больше контекста — это не только «влезло больше текста». Это ещё ресурсы и необходимость проверить, использует ли модель нужные сведения надёжно.

---

## 🔍 Attention не заменяет поиск и проверку истины

В прошлом уроке мы получали векторы документов и ранжировали их по отношению к вопросу. Внутренний attention модели — другой процесс: он работает с представлениями уже доступных позиций.

Если нужного внутреннего документа нет в контексте и нет подключённого инструмента, attention сам по себе не сходит в корпоративную базу и не скачает его. В будущем RAG сначала найдёт нужные тексты, а затем модель сможет использовать их внутри контекста.

Тепловая карта внимания тоже не является готовым объяснением «почему модель так решила». Она показывает одну часть вычисления конкретной головы и слоя, но результат зависит от Value, других голов, MLP, остаточных связей и следующих блоков.

И веса внимания не проверяют факты. Модель может активно использовать устаревшую инструкцию или ложное утверждение. Поэтому наша основная инженерная дисциплина остаётся прежней: источники, контроль контекста, тесты качества и анализ ошибок.

---

## ⚠️ Частые ошибки

**«Attention — это сознательное внимание человека».** Нет. Здесь так называется вычисление весов и взвешенного смешивания векторов.

**«Query — вопрос пользователя, Key — API-ключ».** Нет. Это роли числовых представлений внутри модели; названия совпали с привычными словами.

**«Attention всегда выбирает один самый важный токен».** Обычно нет: информация смешивается из нескольких доступных Value.

**«Баллы attention — косинусы из векторной базы».** Не обязательно. В стандартном scaled dot-product attention используются скалярные произведения обученных Q и K с масштабированием.

**«Запретить будущее можно, просто заменив его баллы нулями».** Недостаточно. После softmax такие позиции всё ещё могли бы получить вес. Маска должна действительно исключать их.

**«Если обучение параллельное, генерация тоже сразу знает весь ответ».** Нет. При генерации будущие токены ещё нужно выбрать.

**«Чем ярче клетка на карте, тем правдивее источник».** Нет. Вес — часть вычисления, а не проверка достоверности или готовое объяснение решения.

## 🧪 Что мы сделаем на практике

**Первый опыт — одна голова внимания.** Возьмём маленькие вручную заданные векторы и матрицы Q, K и V. Посчитаем баллы, масштабирование, softmax и взвешенную сумму. Построим тепловую карту и проверим суммы строк.

**Второй — запрет будущего и роль порядка.** Сравним вычисление без маски и с причинной маской. Изменим последний входной вектор: ранние результаты без маски изменятся, а с маской сохранятся. Затем отдельно проверим свойство перестановки полного attention без позиционной информации.

Это вычислительная лаборатория, а не обученный GPT. Числа заданы вручную, модель не учится понимать русский язык. Мы реализуем одну голову без MLP, остаточных связей и настоящего позиционного механизма. Цель — увидеть принцип, а не выдать маленькую матрицу за полноценную языковую модель.

Все опыты локальные, на NumPy и Matplotlib. Ключи Gemini, OpenRouter и запуск Ollama не нужны.

## ⭐ Главное из урока

1. **Attention обновляет представление позиции через взвешенную информацию от других разрешённых позиций.** Q сопоставляется с K, а веса смешивают V.
2. **Внутренний softmax внимания и выходной softmax словаря — разные операции.** Первый распределяет вклад источников, второй помогает выбирать следующий токен.
3. **Причинная маска исключает будущие позиции.** Она позволяет обучать предсказания на известных последовательностях без подсматривания в продолжение.
4. **Трансформер — не только attention:** нужны позиционная информация, преобразования MLP, остаточные связи, нормализации и множество обученных параметров.
5. **Внимание не гарантирует истину и не заменяет внешний поиск.** Большой контекст и красивые карты не отменяют проверки качества.

## 📚 Глоссарий урока

- **Трансформер** — семейство нейросетевых архитектур, использующих механизмы внимания и другие блоки обработки последовательностей.
- **Attention** — вычисление весов связей и смешивание передаваемых векторов.
- **Query, Q** — вектор запроса позиции для сопоставления с ключами.
- **Key, K** — вектор признаков позиции, по которым она сопоставляется с запросами.
- **Value, V** — вектор информации, который передаётся через взвешенное смешивание.
- **Scaled dot-product attention** — вариант внимания со скалярными произведениями Q и K, масштабированием, softmax и смешиванием V.
- **Self-attention** — внимание внутри одной обрабатываемой последовательности.
- **Cross-attention** — внимание, где запросы и источники ключей и значений могут происходить из разных последовательностей.
- **Голова внимания** — отдельный набор преобразований и вычисления внимания.
- **Causal mask** — маска, запрещающая позиции использовать более поздние позиции.
- **Позиционная информация** — способ учитывать расположение токенов, не только их содержимое.
- **RoPE** — позиционный механизм, использующий вращения представлений Q и K.
- **MLP / feed-forward блок** — преобразование представлений с обучаемыми матрицами и нелинейностями.
- **Residual connection** — добавление вычисленного обновления к прежнему представлению.
- **LayerNorm / RMSNorm** — способы нормализации представлений внутри сети.
- **Авторегрессионная генерация** — последовательное предсказание продолжения с учётом уже выбранных токенов.
- **Логиты словаря** — выходные баллы возможных следующих токенов.
- **KV-cache** — переиспользуемые вычисленные ключи и значения для ускорения генерации.
