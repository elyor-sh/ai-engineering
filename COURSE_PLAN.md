# 🧠 AI Engineering с нуля — план курса

> **Цель курса:** научиться проектировать, строить, оценивать и выводить в продакшн приложения на базе LLM: семантический поиск, RAG-системы, агенты, локальные модели, fine-tuning.
>
> **Формат:** изучаем вместе. Я пишу текст урока → ты делаешь видеопересказ в NotebookLM → смотришь → задаёшь мне вопросы → делаем практику → отмечаем прогресс здесь.

---

## 📌 Кто такой AI-инженер

AI-инженер **не обучает модели с нуля** (это ML research), а **строит продукты поверх готовых моделей**.
Аналогия: backend-разработчик пользуется PostgreSQL, не написав свою СУБД, но обязан понимать индексы, транзакции и планы запросов. Так и здесь: GPT/Claude/Llama мы не обучаем, но понимаем, как они устроены, чтобы использовать их грамотно.

| Роль | Чем занимается |
|---|---|
| ML Researcher | Придумывает новые архитектуры и обучает модели с нуля |
| ML Engineer | Обучает и разворачивает модели на своих данных |
| Data Scientist | Анализирует данные, строит прогнозы, эксперименты |
| **AI Engineer** | **Строит продукты на базе foundation-моделей: RAG, агенты, evals, прод** |

## 🔁 Как мы учимся (цикл одного урока)

1. **Текст урока** — я генерирую `lessons/MM-LL-<тема>/<M.L>-<тема>.md`, например `lessons/01-01-math-minimum/1.1-math-minimum.md` (теория прозой, с аналогиями — удобно для NotebookLM). Номер в имени файла — чтобы в NotebookLM источники не путались.
2. **Видео** — ты загружаешь файл урока в NotebookLM → Видеопересказ / Аудиопересказ (см. промпт ниже).
3. **Вопросы** — смотришь, приходишь с вопросами, разбираем непонятное.
4. **Практика** — код в `lessons/.../practice/` (скрипты или Jupyter).
5. **Самопроверка** — вопросы в конце урока, отвечаешь своими словами.
6. **Прогресс** — ставим `[x]` в этом файле.

### Шаблон каждого урока

`<M.L>-<тема>.md` — теория прозой для NotebookLM (без кода):

- 🧭 **Где мы в курсе** — обязательный блок связности:
  - о курсе в целом и текущая позиция (часть, модуль, урок);
  - «Что было раньше»: предыдущие уроки **текущего модуля** — по 3–5 предложений, **прошлые модули** — сжато, по 2–3 предложения на модуль;
  - сквозные образы курса, если они нужны в уроке (гениальный сотрудник, четыре рычага, двигатель ≠ автомобиль, универсальная розетка, «Знайка»);
  - «Как с этим связан этот урок».
- 🎯 Зачем этот урок (мотивация, что сможешь после)
- 📖 Объяснение «на пальцах» → затем точнее, с аналогиями и примерами
- ⚠️ Типичные ошибки и подводные камни
- 🧪 Что сделаем на практике (словами, без кода)
- ⭐ Главное из урока
- ➡️ **Что дальше** — мостик к следующему уроку
- 📚 Глоссарий урока
- ❓ Вопросы для самопроверки

`practice/` — `README.md` с заданиями и блоками «Мои наблюдения» + код (`.py`, запуск через `uv run`).

### 🎬 Промпт для NotebookLM

**Где:** Студия → ✏️ у «Видеопересказ» → окно «Настройка видеообзора» → поле **«Своя тема»**.
Источники: отмечаем галочкой **только файл текущего урока** (контекст курса уже внутри урока).
Язык видео — в настройках блокнота (⚙️), если его нет в окне настройки.

```
Объясняй на русском языке для начинающего разработчика, который знает
программирование, но не знает машинного обучения. Используй простые
аналогии из жизни, избегай формул. Это один урок из серии: начни с
короткого напоминания из раздела «Где мы в курсе», связывай новое с
тем, что уже было, и используй сквозные метафоры курса. Сделай акцент
на том, ЗАЧЕМ нужна каждая технология и какую проблему она решает.
В конце кратко повтори 3–5 главных мыслей и анонсируй следующий урок.
```

По желанию допиши в конец фокус урока: `Главный акцент: …` (2–3 ключевые идеи из «⭐ Главное из урока»).

> 💡 Один блокнот на весь курс — нормально (на PRO лимита источников хватит). Для видео отмечаем только
> текущий урок, для вопросов в чате — можно все источники (включая `COURSE_PLAN.md`).
> NotebookLM не обновляет файлы сам: если урок правился — удали источник и загрузи заново.

## 🛠 Технический стек

| Что | Чем пользуемся |
|---|---|
| Язык | **Python 3.12+** (основной), TypeScript — опционально |
